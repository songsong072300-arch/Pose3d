# Pose3d 项目交接与网络优化方案

本文是当前项目的交接入口。代码、数据和权重可能继续变化，运行命令以本文件和各脚本的 `--help` 为准；旧实验文档中的目录名不一定代表当前基线。

## 1. 项目目标

输入一段 RGB 视频或单帧图像，检测手腕上佩戴的 DJI Action 4 相机，并预测相机三维包围盒 8 个有固定顺序的二维投影角点。当前实现的输出是“检测框 + 2D 角点”，尚未通过相机内参和 PnP 输出完整 6D 位姿。

整体链路如下：

```text
RGB 帧
  -> YOLO11n 检测 1~2 台相机
  -> 检测框外扩 15%，裁剪并 letterbox 到 224x168
  -> DINOv2-S 角点网络输出 8 张热图
  -> 每张热图取峰值附近 3x3 加权质心
  -> 反变换回原图坐标
```

当前视频推理是逐帧独立处理的：没有目标跟踪、身份关联或时间平滑，因此角点颤动可能来自检测框变化、热图峰值变化、角点顺序错误和模型本身的系统误差。平滑只能减少高频抖动，不能修复错误的角点定位。

## 2. 当前基线

### 2.1 代码职责

```text
pose3d/common/model.py       DINOv2-S 角点网络
pose3d/common/image.py       图像归一化、letterbox
pose3d/train/dataset.py      按实例读取 ROI 和角点标签
pose3d/train/losses.py       热图和坐标损失
pose3d/train/train_heatmap.py角点网络训练入口
pose3d/inference/pipeline.py 单帧检测、ROI、角点解码
pose3d/inference/run_video.py 视频推理和写出
TripoSR/render_dataset.py    BlenderProc 合成 RGB/深度/位姿
TripoSR/generate_corner_heatmaps.py 生成 8 角点标注和热图
TripoSR/build_training_data.py       一键构建数据并导出 YOLO
```

`HCCEPose_src` 和旧的 TripoSR 源码不是当前角点训练必需项。当前渲染依赖 `render_dataset.py`、BlenderProc、`TripoSR/dataset/lm` 下模型/相机配置和根目录 3D 资产；清理时应保留被脚本实际引用的资产，并先用 `--verify-only` 验证，不要直接删除未确认的网格或材质。

### 2.2 当前数据和权重

当前角点训练数据根目录是 `TripoSR/dataset/lm/new_train_pbr`，标签目录为其下的 `new_corner_labels_v1`，不是历史的 `merged_action4`。统计为 2000 张标注帧、3204 个实例；1500 帧 train、500 帧 val，当前没有独立 test。共有 133 个实例部分角点出画，8 个实例完全出画并被 ROI 数据集跳过。

- 角点权重：`checkpoints/角点网络/new_corner_labels_v1.pt`
- YOLO 权重：`outputs/yolo/yolo_new_train_pbr_v2/weights/best.pt`
- YOLO 预测结果：`outputs/yolo_predict/yolo_new_train_pbr_v2`
- 真实测试视频：`head_left_rgb_raw.mp4`
- 推理结果：`outputs/pose3d/head_left_rgb_raw_new_corner_labels_v1.mp4`
- 中间 15 秒片段：`outputs/pose3d/head_left_rgb_raw_new_corner_labels_v1_middle_15s.mp4`

当前角点 checkpoint 记录的验证指标为 ROI 角点误差约 13.91 px、原图约 8.55 px。历史 `checkpoints/merged_action4_smoke.pt` 约为 ROI 4.09 px、原图 2.38 px，但数据集不同，不能直接比较或据此判断新模型退化幅度。

### 2.3 角点网络细节

网络输入 `(3,168,224)`，使用 DINOv2-S/14。最后四个中间层的特征空间分辨率相同，分别用 1x1 卷积投影到 128 通道后拼接，再经过卷积和两次双线性上采样，输出 8 通道 sigmoid 热图。主干大部分冻结，最后两个 Transformer block 和最终 LayerNorm 可训练。

训练时 ROI 由真实角点包围盒计算并外扩，训练集有少量 crop jitter；热图损失是前景加权 Smooth L1，另加归一化 soft-argmax 坐标 Smooth L1。验证使用硬 argmax，而推理使用 3x3 加权质心，存在解码不一致。当前训练默认单一 AdamW 学习率、余弦退火，无 warmup、EMA、梯度裁剪或显式的可见性分支。

## 3. 复现实验命令

从内层项目根目录执行：

```powershell
cd D:\code_work_space\vscode_Work_space\Pose3d\Pose3d
$py = '..\.conda-envs\pose3d\python.exe'
$env:YOLO_CONFIG_DIR = (Resolve-Path '.ultralytics').Path
```

### 3.1 检查现有合成数据

```powershell
& $py TripoSR/build_training_data.py --verify-only `
  --dataset-dir TripoSR/dataset/lm/new_train_pbr `
  --output-split new_train_pbr_v1 `
  --labels-dir new_corner_labels_v1 `
  --yolo-out checkpoints/yolo_new_train_pbr_v1
```

若输出目录不是上述 v1 导出目录，请按实际 `data.yaml` 位置调整 `--yolo-out`。脚本会检查 RGB、角点、热图、train/val 隔离和 YOLO 标签。

### 3.2 从头构建新的合成数据

输出目录必须为空；不要覆盖现有数据。下面只是示例：

```powershell
& $py TripoSR/build_training_data.py --num-images 2000 `
  --dataset-dir TripoSR/dataset/lm `
  --output-split new_train_pbr_v2 `
  --labels-dir new_corner_labels_v2 `
  --yolo-out checkpoints/yolo_new_train_pbr_v2 `
  --frames-per-scene 500 --samples 32 `
  --render-device auto --seed 20261012
```

一键入口依次执行 `render_dataset.py`、`generate_corner_heatmaps.py`、`pose3d.train.export_yolo_labels` 和完整性验证。也可以参考 `docs/新训练数据构建.md` 分步执行。

### 3.3 训练角点网络

当前数据对应的训练命令如下；输出路径使用新文件，避免覆盖现有最好权重：

```powershell
& $py -m pose3d.train.train_heatmap `
  --root TripoSR/dataset/lm/new_train_pbr `
  --labels-dir new_corner_labels_v1 `
  --epochs 30 --batch-size 8 --workers 0 --device cuda `
  --out checkpoints/角点网络/new_corner_labels_v1_retrain.pt
```

`RoiCornerDataset` 会从 `--root/--labels-dir/annotations.json` 读取标注，并按记录中的相对路径读取 `new_train_pbr` 图片。checkpoint 没有保存完整的历史命令，因此这条命令是可用起点，不保证逐 bit 复现既有权重。

### 3.4 训练 YOLO

YOLO 使用 `export_yolo_labels` 生成的 `data.yaml`：

```powershell
& $py -c "from ultralytics import YOLO; YOLO('yolo11n.pt').train(data='checkpoints/yolo_new_train_pbr_v1/data.yaml', epochs=100, imgsz=640, batch=16, workers=0, project='outputs/yolo', name='new_train_pbr_v3')"
```

若本地没有 `yolo11n.pt`，先准备本地权重或允许 Ultralytics 下载。正式实验应把真实视频帧按视频段划分到独立验证集，不能只看合成 val。

### 3.5 推理和截取视频

```powershell
& $py -m pose3d.inference.run_video `
  --video head_left_rgb_raw.mp4 `
  --detector outputs/yolo/yolo_new_train_pbr_v2/weights/best.pt `
  --corner-weights checkpoints/角点网络/new_corner_labels_v1.pt `
  --out outputs/pose3d/current_inference.mp4 `
  --device cuda --detector-conf 0.25 --detector-iou 0.50 --max-det 2
```

当前推理脚本没有时间滤波。需要平滑时，应先保存原始框和角点，再在跟踪/后处理阶段实验 One Euro 或 Kalman，保留原始结果用于比较。

## 4. BoxDreamer 对比

BoxDreamer 的核心是多视图、参考条件的 BB8 completion：已知参考视图的 8 角点热图，查询视图用 learned query/mask token，通过 DINOv2 特征、BB8 embedding、二维位置编码和 BETR Transformer 融合，再恢复查询视图角点。它不是当前项目的单帧检测器，也没有一个可直接复制的成熟视频 tracker；默认 matching 关闭，tracker 分支仍未实现。

当前网络与 BoxDreamer 的主要差距：

1. 当前是单 ROI 的 CNN 解码；BoxDreamer 使用 query token 与图像 patch 的交叉注意力。
2. 当前四层 DINO 特征空间分辨率相同，不是真正的多尺度特征金字塔。
3. 当前没有显式位置编码、角点查询、可见性/出画预测、不确定性估计或参考图像。
4. 当前训练 ROI 主要来自真值框，真实部署则来自有误差的 YOLO 框。
5. 当前验证 argmax、推理质心、训练 soft-argmax 三套解码方式不统一。

## 5. 推荐优化路线

### 第一阶段：先修基线，低风险高收益

1. 用 YOLO 预测框模拟训练 ROI，按真实检测误差校准 15%~30% 外扩和随机抖动；不要始终使用完美真值框。
2. 将几何角点有效性、是否出画、是否被遮挡分开建模。三维包围盒的遮挡角点仍有几何投影真值，不应因为不可见就全部屏蔽；对超出 ROI 或画面的点使用有效性 mask 或额外坐标分支。
3. 增加运动模糊、曝光/白平衡变化、暗光、噪声、JPEG、对比度/伽马和手腕/支架遮挡等增强，使合成域接近真实视频。
4. 统一训练、验证、推理的热图解码；对 logits、温度、阈值和局部质心做验证集调参。
5. 使用参数分组和稳定训练作为起点：decoder 约 `2e-4`、DINO 最后两层约 `1e-6`，5% warmup、cosine、梯度裁剪 1、EMA。它们是待消融的初始值，不是保证有效的固定答案。

### 第二阶段：CornerFormer 结构

保留 YOLO 和单 ROI 设置，先不要直接扩大到 DINOv2-B。建议结构：DINOv2-S 的第 3/6/9/12 层投影到 256 通道，使用轻量 FPN/DPT 解码器恢复真实空间分辨率；增加 8 个有序 corner query，经 4 层 query self-attention 和 image cross-attention 取得角点特征；用 pixel decoder 生成 56 或 112 分辨率特征，再以 query 与像素特征点积产生 8 张 heatmap logits，并可选增加：

- in-frame/validity head；
- 角点坐标和不确定性 head；
- 12 条边的相对向量 Smooth L1 辅助损失。

不要强行约束所有投影边平行/正交，也不要设置固定的最小角点间距；透视投影下这些假设可能不成立，近重合角点也可能是合法结果。Focal、坐标、边、validity 损失的权重需通过消融确定。

### 第三阶段：参考图和时序

如果单帧仍不稳定，再引入 3~5 张质量高的历史帧或 32~64 张模板视图。参考图应独立选择，查询帧的真值不能泄漏到参考分支。视频侧先做 IoU/Hungarian 身份关联，再使用带置信度门控的 One Euro/Kalman；维护 persistent ID、丢失 TTL、异常值检查和重置机制。排序结果后按 x 坐标排列不能保证跨帧身份一致。

只有在相机内参、畸变、角点顺序、模型坐标系和单位都确认后才接 PnP；ROI 裁剪后还要正确变换内参。BoxDreamer 中的 PnP 实现不能直接照搬。

## 6. 评估和交接注意事项

- 用真实视频按连续视频段划分 train/val/test，至少标注 100~300 帧角点；不要把相邻帧随机拆到不同集合。
- 报告每角点误差、平均像素误差、按框对角线归一化的 PCK、出画/遮挡子集和抖动指标（速度/加速度或相邻帧差）。
- 每次实验记录数据版本、ROI 来源、解码方式、随机种子、DINO 缓存版本和 checkpoint 指标。
- `new_train_pbr`、`new_corner_labels_v1`、当前 YOLO/角点权重和推理视频是当前基线资产；大数据和模型文件通常不应提交 Git，应通过外部存储或发布页管理。
- 历史 `merged_action4` 文档和权重保留用于追溯，但不得与 `new_train_pbr` 的指标混用。
