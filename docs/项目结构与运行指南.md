# Pose3d 项目结构与运行指南

本文以 2026-10-10 的代码和数据为准。所有 PowerShell 命令均从内层项目根目录运行：

```powershell
cd D:\code_work_space\vscode_Work_space\Pose3d\Pose3d
$py = '..\.conda-envs\pose3d\python.exe'
$blenderproc = '..\.conda-envs\pose3d\Scripts\blenderproc.exe'
$env:YOLO_CONFIG_DIR = (Resolve-Path '.ultralytics').Path
```

## 1. 项目目标和当前实现

任务图要求从单张 RGB 图像预测物体三维包围盒的 8 个二维角点。本项目针对手腕上佩戴的 DJI Action 4，实际采用两个网络串联：

1. YOLO11n 在整帧中检测 1～2 台相机，输出相机边界框。
2. 每个检测框扩大 15% 后裁剪并 letterbox 到 `224 x 168`。
3. DINOv2-Small 角点网络为每个实例输出 8 张 `168 x 224` 热图。
4. 每张热图取峰值附近的 3 x 3 加权质心，并映射回原图坐标。

当前任务到二维角点结束，没有实现 PnP，因此严格说是“实例检测 + 2D 角点估计”，尚未输出完整 6D 位姿。

角点网络位于 `pose3d/common/model.py`。它取 DINOv2-Small 最后四层中间特征，通过 1 x 1 投影、特征融合和逐级上采样生成 8 通道热图。主干大部分冻结，最后两个 Transformer block 和最终 LayerNorm 参与训练。损失为前景加权热图 Smooth L1 与 soft-argmax 坐标 Smooth L1 的组合。

## 2. 当前有效目录

```text
Pose3d/
├─ pose3d/                         # 本项目网络、训练、推理代码
│  ├─ common/                     # DINOv2 角点模型及图像预处理
│  ├─ train/                      # 角点训练、YOLO 数据导出及分析工具
│  └─ inference/                  # 单图、视频和可视化推理
├─ TripoSR/
│  ├─ render_dataset.py           # BlenderProc 合成渲染核心
│  ├─ generate_corner_heatmaps.py # BOP 标注转角点标注/热图
│  ├─ build_training_data.py      # 渲染、角点标签、YOLO 导出的一键入口
│  └─ dataset/lm/                 # 合成数据和 BOP 模型
├─ 3D资产/                         # 渲染所用服装、杂物等 OBJ/PBR 资产
├─ frames/                        # 从真实测试视频抽取的 20 帧
├─ checkpoints/                   # 数据导出目录和角点权重
├─ outputs/                       # YOLO 训练、预测和其他实验输出
├─ docs/                          # 项目文档
└─ requirements-pose3d.txt        # 普通 Python 训练/推理依赖
```

当前主要资产：

- 角点训练集：`TripoSR/dataset/lm/merged_action4`，4617 帧、9234 个实例；按 scene 划分为 3693/461/463 个 train/val/test 帧。
- 最好角点权重：`checkpoints/merged_action4_smoke.pt`，记录的验证 ROI 角点误差为 4.09 px，映射到原图为 2.38 px。
- YOLO 最好权重：`outputs/yolo/yolo_new_train_pbr_v2/weights/best.pt`。
- YOLO 真实帧预测：`outputs/yolo_predict/yolo_new_train_pbr_v2`。

YOLO v2 实验实际使用 `checkpoints/yolo_new_train_pbr_v1/data.yaml`、`imgsz=640`、`batch=16`、100 epochs。最后一轮合成验证集指标为 precision 0.9957、recall 0.9500、mAP50 0.9737、mAP50-95 0.8483。该验证集不能替代真实视频评估。

## 3. 环境

先安装与显卡驱动匹配的 PyTorch，再安装普通依赖和 YOLO：

```powershell
& $py -m pip install -r requirements-pose3d.txt
& $py -m pip install ultralytics blenderproc
```

角点模型通过 `torch.hub` 加载 DINOv2。代码会优先查找用户 torch hub 缓存和项目 `.torch-cache/hub`，均不存在时才访问在线仓库。离线训练和推理前必须确保其中一处已有 DINOv2 源码与权重缓存。合成渲染还依赖 BlenderProc、`TripoSR/dataset/lm/models` 中的目标网格，以及根目录 `3D资产`。

## 4. 构建训练数据

### 4.1 一键构建一批新数据

输出目录必须不存在或为空。下面生成 1000 张图片，按 200 帧一个 scene 写入 BOP 数据，随后生成角点标签并导出 YOLO 数据：

```powershell
& $py TripoSR\build_training_data.py `
  --num-images 1000 `
  --dataset-dir TripoSR\dataset\lm `
  --output-split action4_train_pbr_v3 `
  --labels-dir action4_corner_labels_v3 `
  --yolo-out checkpoints\action4_yolo_v3 `
  --frames-per-scene 200 `
  --seed 20261010 `
  --samples 16 `
  --render-device cpu
```

该入口依次运行：

```text
render_dataset.py
  -> BOP RGB/depth/scene_gt/scene_camera
generate_corner_heatmaps.py
  -> annotations.json + splits.json + 8 通道 npz 热图
pose3d.train.export_yolo_labels
  -> YOLO images/labels/data.yaml
verify()
  -> 完整性检查和 build_report.json
```

快速冒烟测试建议先使用 `--num-images 12 --frames-per-scene 6 --samples 4`。只复查已有产物可添加 `--verify-only`，同时让 `--num-images` 等于已有标注记录数。

### 4.2 分步运行

需要调渲染参数时，先直接生成一个全新的预览目录：

```powershell
& $blenderproc run TripoSR\render_dataset.py 24 `
  --dataset-dir TripoSR\dataset\lm `
  --preview-dir TripoSR\preview_action4_v3 `
  --preview-yolo-labels `
  --render-device cpu `
  --seed 20261010
```

确认构图、遮挡、目标尺寸、服装和光照后，再去掉 `--preview-dir` 并指定新的 `--output-split` 生成正式 BOP 数据。然后运行：

```powershell
& $py TripoSR\generate_corner_heatmaps.py TripoSR\dataset\lm `
  --image-split action4_train_pbr_v3 `
  --output-root TripoSR\dataset\lm\action4_corner_labels_v3 `
  --split-mode scene `
  --val-scene-count 1 `
  --test-scene-count 1

& $py -m pose3d.train.export_yolo_labels `
  --root TripoSR\dataset\lm `
  --labels-dir action4_corner_labels_v3 `
  --out checkpoints\action4_yolo_v3
```

必须按 scene 划分，避免同一渲染序列的近重复帧同时进入训练集和验证集。若要求 train/val/test 都非空，至少生成 3 个 scene。

注意：角点训练时 `RoiCornerDataset` 会根据 `annotations.json` 中的坐标重新生成适合 ROI 尺寸的高斯热图；磁盘上的 `.npz` 主要用于数据审计和完整性验证，并非训练加载的直接监督输入。

## 5. 训练网络

### 5.1 训练角点网络

使用当前 `merged_action4` 数据复现训练：

```powershell
& $py -m pose3d.train.train_heatmap `
  --root TripoSR\dataset\lm\merged_action4 `
  --labels-dir corner_labels `
  --epochs 50 `
  --batch-size 8 `
  --workers 0 `
  --device cuda `
  --amp `
  --out checkpoints\merged_action4_v2.pt
```

模型以验证集平均 ROI 角点像素误差最小为保存标准。Windows 下建议先保持 `--workers 0`；显存不足时降低 batch size。新权重同时包含完整 `model_state` 和轻量 `decoder` 字段，推理代码也兼容现有只含 `model_state` 的 `merged_action4_smoke.pt`。

### 5.2 训练 YOLO

复现当前 v2 的主要参数：

```powershell
& $py -c "from ultralytics import YOLO; YOLO('yolo11n.pt').train(data=r'checkpoints/yolo_new_train_pbr_v1/data.yaml', epochs=100, imgsz=640, batch=16, workers=0, device=0, seed=2026, project=r'outputs/yolo', name='yolo_new_train_pbr_v3')"
```

训练新导出的 v3 数据时，只需把 `data=` 改成 `checkpoints/action4_yolo_v3/data.yaml`。不要覆盖 v2 目录；使用新的 `name` 便于比较实验。

## 6. 推理和测试

YOLO 单独检测 `frames`：

```powershell
& $py -c "from ultralytics import YOLO; YOLO(r'outputs/yolo/yolo_new_train_pbr_v2/weights/best.pt').predict(source='frames', conf=0.25, iou=0.5, max_det=2, save=True, project='outputs/yolo_predict', name='yolo_new_train_pbr_v2_recheck')"
```

单张图片运行完整两阶段管线：

```powershell
& $py -m pose3d.inference.predict_image `
  --image frames\frame_00000s.jpg `
  --detector outputs\yolo\yolo_new_train_pbr_v2\weights\best.pt `
  --corner-weights checkpoints\merged_action4_smoke.pt `
  --out outputs\pose3d\frame_00000s.jpg
```

原始视频运行完整管线：

```powershell
& $py -m pose3d.inference.run_video `
  --video path\to\test.mp4 `
  --detector outputs\yolo\yolo_new_train_pbr_v2\weights\best.pt `
  --corner-weights checkpoints\merged_action4_smoke.pt `
  --max-det 2 `
  --out outputs\pose3d\test_corners.mp4
```

## 7. 已移除的 HCCEPose_src

项目整理时已经移除 `HCCEPose_src`。原目录仅是上游参考项目，当前代码没有任何对它的 import、脚本调用或路径引用。当前合成数据由独立的 `TripoSR/render_dataset.py` 通过 BlenderProc 生成，角点网络和 YOLO 训练也都不依赖 HCCEPose，删除不会影响当前数据构建、网络训练和推理。

需要追溯原始实现时，直接访问上游仓库 <https://github.com/WangYuLin-SEU/HCCEPose>。

## 8. TripoSR 中哪些部分仍有作用

项目整理时已经移除 TripoSR 原始的单图建模网络、Gradio 页面、示例和第三方编译源码。现在 `TripoSR` 只保留本项目的合成数据管线、许可证、渲染说明和本地训练数据。

当前训练链路必需：

- `build_training_data.py`
- `render_dataset.py`
- `generate_corner_heatmaps.py`
- `dataset/lm/models` 和所选 BOP 数据

如果以后需要重新从单图生成 3D 网格，应单独克隆官方 TripoSR 项目，不再把它与训练数据生成代码混放。

## 9. 数据与 Git 管理

训练数据、训练输出、缓存和模型参数均保留在本机，不提交 Git：

```text
TripoSR/dataset/lm/*train_pbr*/
TripoSR/dataset/lm/*corner_labels*/
TripoSR/dataset/lm/merged_action4/
checkpoints/
outputs/
weights/
*.pt
```

`3D资产` 和 `TripoSR/dataset/lm/models` 是重建合成数据所需的输入资产，通过 Git LFS 提交。GitHub 克隆后需安装 Git LFS 并运行 `git lfs pull`。数据来源、生成命令、seed、scene 划分和指标应通过文档或 manifest 记录。

## 10. 已知限制

- 真实 `frames` 只有 20 张且没有角点真值，只能做定性检查，不能报告真实角点误差。
- 已用 `frame_00000s.jpg` 验证完整管线可运行，但部分预测角点越出检测框或发生聚集；当前角点模型尚不能据此认定达到可靠几何精度。
- 合成数据每帧两个实例，和真实场景分布可能不完全一致。
- 目前 YOLO 框与角点训练裁剪框存在分布差异；训练集使用真值角点框并做 5% jitter，推理使用 YOLO 框。
- 相机内参/畸变、时序平滑、PnP 和最终 6D 位姿尚未进入当前管线。
- `render_dataset.py` 体积较大，后续宜拆成资产加载、场景随机化、相机采样、渲染输出四个模块，但应先建立固定 seed 的回归测试。
