# 基于 BoxDreamer 的 Pose3d 网络优化设计

日期：2026-10-15。本文是对《项目交接与网络优化方案》的代码核对与细化设计，尚未实现或训练新网络。

## 1. 结论与范围

推荐保留 YOLO → 实例 ROI → 有序 BB8 角点的任务接口，分三个版本推进：

1. **B0：可信基线**。修正出画角点监督、检测 ROI 分布和评估解码，明确实际使用的 checkpoint。
2. **V1：单帧 CornerFormer**。DINOv2-S + 图像 patch 交互 + RGB 细节分支 + 有序角点联合解码，让 Transformer 成为主要预测路径。
3. **V2：参考条件 CornerFormer**。加入带已知 BB8 的模板参考图，将 BoxDreamer 的跨视图补全机制迁移进来，再评估历史帧参考。

这里“性能”优先指角点精度和视频稳定性，同时记录显存、单 ROI 时延和整帧时延。当前没有同一测试集上的 BoxDreamer/Pose3d 对照，不能量化两者的精度差距，也不能断言现有误差主要由网络容量造成。

## 2. 当前实际状态：文档、代码、权重需要分开看

### 2.1 当前代码已经不是纯 CNN 解码器

核对 `pose3d/common/model.py` 后，实际结构为：

```text
ROI RGB [B,3,168,224]
  → DINOv2-S/14 最后四层特征，各为 [B,384,12,16]
  → 各自 1×1 投影到 128 通道
  ├─ 四层拼接 → CNN 融合 → 24×32 → 48×64 → 168×224
  │                                           → 8 通道 base logits
  ├─ 最后一层投影 + learned position
  │   → 8 个 corner query、2 层 TransformerDecoder
  │   → query 与 48×64 像素特征点积 → query logits
  └─ CNN 融合特征全局均值 → 11 参数投影头 → coarse_corners

heatmaps = sigmoid(base_logits + query_scale × query_logits)
```

训练加入投影角点回归和热图/投影一致性损失；视频推理只消费 `heatmaps`，没有利用 `coarse_corners`。加载旧权重时缺失的 query 分支被 `query_scale=0` 禁用。因此，“代码中有 attention”不代表某个推理结果已使用 attention。

交接文档中“没有显式位置编码、角点查询”的结论只适用于旧基线；当前有 learned image position 和 corner query，但没有参考分支。`get_intermediate_layers(n=4)` 取最后四层，而不是第 3/6/9/12 层。

## 3. BoxDreamer 真正值得迁移的机制

主要依据：`boxdreamer/src/models/BoxDreamerModel.py`、`modules/backbone/betr.py`、`modules/encoder/dinov2.py`，以及 `configs/model/transformer.yaml`。

| 项目 | 当前 Pose3d 代码 | BoxDreamer 所查配置与实现 | 迁移建议 |
|---|---|---|---|
| 图像编码 | DINOv2-S/14，微调最后两层 | DINOv2-B/14 with registers，冻结编码 | 先保持 S；B/register 另做消融 |
| 已知几何条件 | 无参考图 BB8 输入 | 参考视图 BB8 热图 patch embedding | V2 的核心输入 |
| 查询表示 | 8 个有序角点 query | 查询视图每个 patch 的 BB8 embedding 替换为共享 learned token | 两者不等价，不应直接类比 |
| 信息交换 | 两层角点 decoder 读取最后一层图像 memory | 所有视图 patch 展平为 `B×(N·P)×D` 后做全局 self-attention | V1 增加图像 patch 交互；V2 增加跨视图交互 |
| 位置 | 固定长度 learned image position | 每视图二维 sin/cos 位置编码 | 改成可支持矩形网格的位置编码 |
| 输出恢复 | 插值、CNN、query 热图修正 | 每个查询 patch 线性输出 `14²×8`，unpatchify | 做独立 patch 恢复对照，主方案保留细节分支 |
| 训练目标 | 热图、坐标、投影、一致性 | 所查默认配置主要为查询视图 BB8 Smooth L1 | 不把 Focal/几何损失误称为原论文实现 |
| 时序跟踪 | 逐帧独立 | 配置关闭；启用 tracking 分支会抛 NotImplementedError | 跟踪单独建设 |

BoxDreamer 所查配置的 BETR 是宽度 768、12 层、8 heads；这和当前 128 维、2 层 decoder 不在同一容量级别。但它同时拥有参考图和已知参考几何信息，不能把差异全部归因于层数。

其核心数据流是：

```text
参考图 RGB → DINO tokens ─┐
参考图已知 BB8 → embedding ├→ RGB + BB8 + 2D position
查询图 RGB → DINO tokens ─┤          ↓
查询图未知 BB8 → mask token┘   跨视图 patch self-attention
                                    ↓
                           查询 patch → 8 张角点热图
```

源码 BETR 的 patchify/unpatchify 和若干位置编码逻辑假定正方形，不能直接接入本项目 168×224。其热图输出还映射到 [-1,1]，不能直接套用本项目的 sigmoid 阈值。

## 4. 优先排查的具体问题

### 4.1 出画监督存在输出域冲突

`dataset.py` 只跳过八个角点全部出画的实例，部分出画样本仍对八个角点生成热图、回归坐标。`losses.py` 没有逐角点 mask。

但 soft-argmax 是 ROI 网格上的凸组合，无法输出 ROI 外坐标。出画点对应的高斯只能在边界留下尾部，远离边界则近乎全零，却仍被要求回归 ROI 外坐标。额外的几何一致性也会把这两种输出要求绑在一起。

应明确三类标志：

- `geom_valid`：几何标注可信、有限且相机深度有效；不能用“在画面内”替代。
- `in_roi`：角点中心是否位于当前 ROI 对应的真实图像内容区域，需结合原图边界和 letterbox 内容 mask。
- `occluded`：角点/物体被遮挡；只有可靠标签才训练此项。三维包围盒角点不一定落在真实表面上，不能仅凭深度差就定义其可见性。

热图坐标损失只监督 `geom_valid & in_roi`；几何有效但在 ROI 外的角点交给不受 [0,1] 限制的坐标分支。遮挡且仍在 ROI 内的几何角点继续接受监督。mask 后按有效点数归一化，空集合返回零，不能产生 NaN。

### 4.2 当前 crop jitter 没覆盖真实检测误差

训练框来自真值角点，`expanded_corner_box()` 的 min/max 保护倾向于保住完整角点包围盒，再裁到画面；因此 0.05 jitter 不能模拟 YOLO 框的偏移、缩小和截断。

应离线保存实际 YOLO 框，与实例按 IoU 关联；统计中心偏移、宽高误差、漏检率与目标尺寸。起始可用 50% GT 扰动框 + 50% 匹配检测框，比例通过验证调整。分开评估定位误差与检测漏检，不把漏检实例悄悄从端到端结果中删除。

训练 split 的预测框最好由未训练过该样本的 detector 或折外预测产生；至少记录 detector 训练来源，避免把过于理想的训练集检测框当成部署分布。外扩从 0.15/0.25/0.35 做验证，不能只扩大而不考虑小目标有效分辨率下降。

### 4.3 当前新增头有局限，但需要消融确认贡献

- query 读取的是最后一层投影；没有额外任务专用的 image-token 更新。DINO 本身已有全局注意力，这里缺少的是角点任务适配后的 patch 交互，而不是“完全没有全局上下文”。
- 四层 DINO 特征同为 12×16。插值到全分辨率不会产生新的图像细节，需要额外的高分辨率观测路径。
- 几何头从全局平均特征预测一个投影矩阵，空间信息被压缩；初始接近八点重合。它能约束投影关系，但不是已知内参和长宽高下的严格刚体位姿模型。
- 当前投影参数的 tanh 范围是人为限制，可能限制部分视角；未核对真实标签范围前不应增大其权重。
- 所有随机初始化解码器和 DINO 尾层共享默认 `1e-5` 学习率，可能妨碍新分支适应。checkpoint 未记录历史实际 lr，不能据此断言之前的运行都用了默认值。
- 训练对 sigmoid 热图做 `softmax(50×heatmap)`，验证硬峰值，推理局部质心且低于 0.15 则丢点，三者目标不一致。峰值也不是校准后的角点正确概率。

## 5. V1：单帧 CornerFormer 结构设计

### 5.1 推荐起始配置

保持输入 H×W=168×224，不同时改输入分辨率和 backbone。统一隐藏维 256，8 heads；所有尺寸显式传递 H、W，不使用 `sqrt(P)` 推导矩形网格。

```text
ROI [B,3,168,224]
 ├─ DINOv2-S/14，取 block 3/6/9/12（实现索引 2/5/8/11）
 │    → 4×[B,384,12,16]
 │    → 每层 1×1 Conv 到 256，拼接后融合
 │    → 矩形 2D sin/cos PE
 │    → 2 层 image self-attention → memory [B,192,256]
 │                          ├──────────────────────────────┐
 │                          ↓                              ↓
 │                 8 个固定语义 corner query          pixel decoder
 │                 + canonical XYZ embedding          24×32 → 48×64
 │                          ↓                              ↓
 │                 4 层 query decoder                 84×112 融合特征
 │                 每层：query self-attention               ↑
 │                      + image cross-attention             │
 │                          ↓                              │
 │                    Q [B,8,256]                          │
 └─ 浅层 RGB CNN，stride 2/4，GroupNorm ────────────────────┘

Q 与 pixel features 点积 → logits [B,8,84,112]
Q → direct_xy [B,8,2]（线性输出，允许出 ROI）
Q → in_roi_logits [B,8]
```

RGB 细节分支建议 stride-2 的 32 通道卷积、stride-4 的 64 通道卷积，加各尺度卷积块，与 DINO 解码特征投影、插值后融合；最终像素特征为 256 通道。它补充真实纹理和边界信息；单纯对同分辨率 ViT feature 做 FPN 重采样不等于获得真实多尺度输入信息。

corner query 的 canonical XYZ 沿用标签二进制 XYZ 顺序：X 最慢、Z 最快。八个通道是固定对象角点身份，不能按图中左右排序，也不做 Hungarian 角点重配以掩盖角点身份错误。

这不是在旧 CNN 输出上继续叠加小幅修正。V1 的主要热图由任务适配后的图像特征与 corner query 共同生成，旧 `base_logits + query_scale×query_logits` 作为独立基线保留。

### 5.2 热图与坐标定义

新模型返回原始 logits，取消训练接口内的 sigmoid。对每角点在有效内容网格上执行空间 softmax，得到 `P_k(u,v)`；高斯标签归一化为 `G_k`，使用分布交叉熵或等价的 KL 监督。

训练、验证、推理共享同一个概率分布期望解码：`xy_heatmap = Σ P_k(u,v)·(u,v)`。温度先取 1，必要时只在验证集上调整并写入 checkpoint。相比对 sigmoid 值乘 50 后再 softmax，这样概率含义更明确。

需注意多峰热图的均值可能落在两峰之间，必须记录熵、最高峰和第二峰，而不是默认期望解码总更好。把“局部峰值解码 + 对应训练目标”作为独立对照；最终采用哪种由冻结验证协议决定。

热图坐标到 ROI 坐标使用明确的像素中心变换，例如输出分辨率减半时 `x_roi=(x_hm+0.5)×2-0.5`，标签执行逆变换；随后复用 letterbox 的实际 `scale_xy` 和 padding 还原原图。角点中心恰在边缘时的半像素约定需要单独验证。

坐标分支预测相对 ROI 的归一化坐标，可小于 0 或大于 1。所有 `geom_valid` 点监督 direct_xy；ROI 内点额外监督热图并保持两路一致。推理用经验证校准的 in_roi 判断选用热图或 direct_xy，并保留分支来源、分数与全部原始坐标。出 ROI 点外推可能不可靠，应单列评估。

### 5.3 损失与几何约束

先用以下组合，系数只是归一化后消融的起点：

```text
L = 1.0 L_heatmap_distribution
  + 1.0 L_heatmap_xy          # 归一化坐标，geom_valid & in_roi
  + 1.0 L_direct_xy           # 归一化坐标，geom_valid
  + 0.1 L_in_roi              # BCEWithLogits，geom_valid
```

首轮不叠加当前 11 参数投影头和一致性损失，避免同时验证太多假设。基线稳定后逐个加入：

- `0.1 L_head_consistency`：仅 ROI 内两路坐标一致，检查是否互相拉向错误解。
- `0.1 L_edge`：固定 12 条三维盒边对应的二维有向边向量 Smooth L1，两端均有效才计算；它与坐标损失部分冗余，需要实测增益。
- 几何投影头：设为显式可关闭的辅助项，对比分支本身、约束热图、推理融合三种方式，不能默认它改善输出。
- 不确定性：确有异常点拒绝需求后再加入受约束的方差/NLL，并评估校准，不能仅用可学习置信度降低困难样本权重。

不约束投影边平行/正交，不规定最小角点距离，不用逐帧重新排序解决固定角点身份。已知内参和实物尺寸后，可另试刚体投影/PnP 一致性；真实畸变需要一并处理。

## 6. V2：参考条件网络，迁移 BoxDreamer 的主要能力

### 6.1 参考数据如何获得

为 DJI Action 4 建立 32–64 个覆盖视角的固定模板起点，明确模型轴、角点身份、尺寸与真实外观。模板 RGB、BB8、裁剪变换必须成套保存；模板仅来自独立渲染或训练数据。

检索先使用 query 图像与模板图像的 DINO 描述子相似度，取 2–4 个参考；增加视角多样性，避免全是近重复视图。32–64 只是覆盖起点，须检查正背面、侧面、俯仰和遮挡下的检索召回，而不是假定模板数量足够。禁止用 query 真值姿态选择最优模板作为正式指标。

### 6.2 条件融合接口

每个参考在相同 ROI 坐标下提供 RGB token 和 8 通道 BB8 heatmap，经 heatmap patch embedding 后与 RGB、二维位置编码相加。query 的 BB8 槽位使用 learned mask token，模型 forward 的 query 输入中不含真值角点或由其构造的热图。

起始方案：共享 V1 编码器；query patch 对参考 memory 做 2 层 cross-attention，再交给 V1 的角点/pixel decoder。增加 reference/query 类型编码、缺失参考 mask；训练做 reference dropout，使没有可靠参考时仍能走单帧路径。

另外保留一个更接近 BoxDreamer 的对照：把 1 个 query 与 R 个参考的 patch 统一展平做 BETR self-attention，线性输出查询 patch 的 `14²×8` logits，再按矩形网格 unpatchify。这个对照用于判断参考融合方式，不与 RGB 细节分支、backbone 同时改动。

单帧有 192 patch，R=4 时共有 960 patch；全局注意力矩阵元素相对单视图约增至 25 倍，整体运行时不一定同比增加。模板编码可缓存，但跨视图融合仍有成本。优先使用 PyTorch SDPA，并实测目标设备上的后端与显存，不预设需要额外安装 FlashAttention。

### 6.3 历史帧参考在固定模板之后

必须先做目标身份关联，再为每个 persistent ID 维护少量参考。高质量模板/人工标注参考与模型预测的历史参考需区分来源；后者要经过置信度、模糊度、几何异常检查，并有过期、清空、重检测机制。

训练时对参考角点加入符合误差分布的扰动和缺失，减少“训练参考全正确、部署参考有误”的差异。不要无门控地把上一帧预测作为下一帧真值，避免漂移。

## 7. 数据和训练协议

先在现有数据上完成结构消融，再扩充数据；候选扩充起点为 1–2 万张合成帧和 100–300 帧可靠真实角点标注，数量按姿态/场景覆盖和学习曲线调整。真实难例优先包含运动模糊、暗光、反射、手腕/支架遮挡、正背面混淆、出画和两个实例交叠。

真实数据按视频/连续片段隔离 train、val、test，必要时在片段间留时间间隔；合成数据按 scene 隔离。已有加入 YOLO 训练的真实帧及相邻重复帧不再当独立测试。真实检测框标注不能直接替代八角点标注；难以人工辨认的隐藏角点要用一致的几何拟合与质量检查。

增强分两类：光照、颜色、噪声、模糊、压缩和遮挡只改图像；裁剪、缩放、旋转、透视变换必须同步更新角点、有效性、模板条件及变换链。水平翻转可能产生不符合实物外观的镜像，默认关闭；如启用需明确语义顺序和适用性。

训练起点：

| 项 | 建议 |
|---|---|
| DINO | 先完全冻结训练新头；主训练再评估解冻末两层 |
| 新解码器/RGB 分支 lr | AdamW `2e-4` 起步 |
| DINO 解冻 lr | `1e-6` 起步，和新头分组 |
| Weight decay | 新权重先试 `0.01`，bias/norm/位置与 query embedding 单独无衰减组 |
| 调度 | 总 optimizer steps 的 5% warmup，随后 cosine |
| 稳定性 | 梯度裁剪 1.0，CUDA AMP，EMA≈0.999 做对照 |
| 有效 batch | 16 起步；显存不足时梯度累积，明确实际 optimizer steps |
| 停止策略 | 固定计算预算记录曲线，正式训练按验证指标早停，不把 30 epoch 当固定充分条件 |

这些数值不是由 BoxDreamer 原配置直接复制，也不是已验证最优值。按参数组记录梯度范数、实际 lr、各损失和输出分支误差，避免只看总 loss。

## 8. 实验矩阵和验收

### 8.1 按顺序回答问题

| 编号 | 唯一主要变化 | 要回答的问题 |
|---|---|---|
| A0 | 同一评估器重测三个现有 checkpoint | 当前最好权重究竟是哪一个？ |
| A1 | A0 + 出画 mask + 验证/推理解码对齐 | 监督矛盾和评估差异有多大？ |
| A2 | A1 + GT/实际检测 ROI 混合训练 | 检测框分布是否为主要瓶颈？ |
| A3 | A2 + 分组 lr/warmup，其他稳定措施分别加 | 新头是否受训练配置限制？ |
| B1 | 固定 A3 数据与优化，V1 结构；初始可关闭 direct/outside 路由 | 单帧架构组合是否有收益？ |
| B1a–d | 从 B1 分别移除 RGB 分支、patch attention、query 联合交互、改回末四层 | 结构收益来自哪一部分？ |
| B2 | B1 + direct_xy/in_roi 出画路径 | 能否恢复出 ROI 几何角点且不损害框内点？ |
| B3 | B2 单独加入边/几何/一致性辅助项 | 几何损失是否值得保留？ |
| C1 | 最佳单帧模型 + 固定模板参考 | 已知参考 BB8 是否解决歧义？ |
| C2 | C1 的参考热图移除或替换；相同检索参考 | 收益来自参考几何还是仅更多 RGB？ |
| C3 | 更换 DINO-B/register，其他协议固定 | backbone 容量是否值得额外成本？ |
| D1 | 最佳空间模型 + 身份关联和滤波 | 时间稳定性和延迟的权衡如何？ |

B1 是结构包对照，其内部贡献由 B1a–d 补充验证；B1 如关闭出画路径，则只在 ROI 内子集比较主结构，完整评估从 B2 开始。决定采用的核心对照至少跑 3 个种子，不能把约 2% 的单次指标差异直接作为结论。

同时准备接近 BoxDreamer 的 patch-unpatchify 参考融合对照，独立于主路线；有可用兼容预训练权重时再测试迁移，层宽不同不能把完整 BETR 权重直接载入 V1。

### 8.2 必须报告的结果

- **定位诊断**：GT ROI 与预测 ROI 的角点误差、逐角点误差、PCK@0.05/0.1。归一化分母统一用 GT 二维投影框对角线，不能让检测框变大改变指标。
- **端到端**：实例召回与阈值内八角点成功率；漏检、低置信度弃点明确计入失败，同时单独报告可用点覆盖率。
- **困难子集**：小目标、遮挡、出画、模糊、正背面；区分 ROI 内定位与 ROI 外外推。
- **视频**：按 persistent ID 的角点残差变化、P95 异常跳变和轨迹断裂。原始相邻帧差包含真实运动；有真值时看残差，无真值时只作稳定性代理，不能宣称等于定位精度。
- **效率**：固定硬件、batch、精度模式和预热；报告单 ROI、1/2 目标整帧 p50/p95 时延及峰值显存，明确包含/不包含 YOLO 和数据搬运。

建议把“相同真实独立测试集上平均归一化误差下降至少 15%–20%、PCK 提升、覆盖率不降、困难子集无明显退步”设为新结构进入部署候选的工程目标，而非预期收益承诺。测试集不用于选超参数；先用 val 冻结配置，再一次性报告 test。

若 GT ROI 好而预测 ROI 差，优先检测框和 ROI 训练；合成好而真实差，优先域差和真实标注；GT ROI 合成/真实都差，再重点扩大架构与优化预算。只有三个方向都可测，才能判断哪一项值得投入。

|---|---|

新 checkpoint 必须保存：architecture/version、模型超参数、角点顺序、输入/热图尺寸、backbone 来源、解码及温度、ROI 配置、数据版本/划分哈希、seed、优化器/scheduler/scaler 状态、EMA 状态与验证指标。新架构严格校验关键权重；旧权重兼容保持显式，不让 `strict=False` 隐藏新模型漏加载。

最先实施 B0/A0–A3 并完成 V1 可训练版本。固定模板参考是下一阶段重点；当前不应把继续堆投影辅助损失或增加视频平滑当作主要网络升级。
