# 双 DJI ACTION4 八角点检测代码说明

## 任务边界

当前交付目标是从单目 RGB 图像中检测相机三维包围盒的 8 个二维投影角点。网络不计算 6D 位姿，也不需要相机内参或 PnP。

真实视频每帧有两个同款实例，因此完整路径为：

```text
RGB 帧 -> YOLO 检测两个实例 -> 分别裁剪 ROI -> 共享角点网络
-> 每个 ROI 输出 8 通道 Heatmap -> 每通道提取一个角点
```

## 为什么没有照搬 BoxDreamer

BoxDreamer 使用参考 RGB、参考角点 Heatmap 和查询 RGB，目标是泛化到训练时没有见过的物体。本项目只处理一个固定相机实例，而且任务规定网络输入为单张 RGB，因此删除参考分支。

保留的论文设计包括：

- DINOv2 预训练视觉特征；
- 8 个有固定通道顺序的角点 Heatmap；
- Heatmap 粗监督和角点坐标细监督；
- 遮挡情况下根据全局目标结构推断角点。

## 主网络

默认模型是 `CornerHeatmapNet`：

```text
RGB ROI (3,168,224)
-> 冻结 DINOv2-Small
-> 最后四个中间层特征，各为 (384,12,16)
-> 1x1 Conv 投影到 128 通道
-> 拼接并卷积融合
-> 两级双线性上采样和卷积
-> 恢复到 (168,224)
-> 1x1 Conv
-> 8 通道 Heatmap
```

DINOv2-Small 总参数约 22M。默认冻结 backbone，只训练约 1.16M 解码器参数，适合当前约 2950 个单实例 ROI 的数据规模。

## ROI 与坐标变换

`RoiCornerDataset` 将一帧中的两个实例拆成两个训练样本。裁剪框增加随机尺度和中心扰动，以模拟 YOLO 检测误差。裁剪后使用 Letterbox 缩放到 `168x224`，不会改变物体宽高比。

角点从原图变换到 ROI：

```text
p_roi = (p_full - crop_origin) * scale_xy + letterbox_padding
```

推理时执行严格逆变换：

```text
p_full = (p_roi - letterbox_padding) / scale_xy + crop_origin
```

## 损失函数

训练采用 BoxDreamer 的粗细双监督思想：

```text
L = L_heatmap + 2.0 * L_coordinate
```

- `L_heatmap`：前景加权 Smooth L1，防止稀疏标签导致全零预测。
- `L_coordinate`：使用可微 spatial soft-argmax 得到 8 个坐标，再计算归一化 Smooth L1。

验证阶段使用每通道 argmax 与真值之间的平均像素距离选择最佳 checkpoint。

## 训练

默认训练单实例 ROI 和 DINOv2-Small：

```bash
conda run -n pose3d python -m pose3d.train.train_heatmap \
  --root TripoSR/dataset/demo-bin-picking \
  --epochs 30 --batch-size 8 --workers 4 --amp \
  --out checkpoints/dino_corner_net.pt
```

## 单图测试

```bash
conda run -n pose3d python -m pose3d.inference.predict_image \
  --image frames/frame_00000s.jpg \
  --detector checkpoints/dji_action4_yolo.pt \
  --corner-weights checkpoints/dino_corner_net.pt \
  --out outputs/corners.jpg
```

脚本同时保存可视化图片和 JSON。JSON 中每个实例包含检测框、8 个角点坐标、检测置信度和各角点置信度。

## 视频测试

conda run -n pose3d python -m pose3d.inference.run_video \
