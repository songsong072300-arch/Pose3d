## 一、数据加载：RoiPoseDataset.__getitem__ 逐行

文件：`pose3d/roi_pipeline.py:24-28`。这是全链路的起点，**决定了网络"看到什么"**。

### 1.1 拆包与读图

```python
r, ins = self.items[i]
im = Image.open(self.root / r['image']).convert('RGB')
W, H = im.size                       # (960, 720)，PIL 是 (宽,高) 在前
p = np.asarray(ins['corners_2d'], np.float32)   # (8,2) 本实例 8 个角点原图坐标
```

- `self.items` 是初始化时拍扁的结果：一帧两机 → 两个 `(帧记录r, 实例ins)` 元组，
  1475 帧 × 2 = **2950 个样本**
- 打开的是**整张原图**，两台相机共用一张图，靠后续裁剪分离
- `p` 是这台相机**自己的**角点真值（渲染时各自记录 R/t，投影时分开算）

### 1.2 算裁剪框：外接矩形 + 15% 外扩 + 夹回图界

```python
x1, y1 = p.min(0)                   # 沿8个点取每列最小 → (min_x, min_y)
x2, y2 = p.max(0)                   # → (max_x, max_y)
dx, dy = (x2-x1)*self.pad, (y2-y1)*self.pad      # pad=0.15
xa, ya, xb, yb = max(0,x1-dx), max(0,y1-dy), min(W,x2+dx), min(H,y2+dy)
```

- `p.min(0)`：轴 0 是"8 个点"，压掉它，剩每列（x 列、y 列）各自的最小 → 8 点外接矩形
- 外扩 15% 给网络留背景上下文，防止角点贴边
- `max(0,·)/min(W,·)` 是**防御**：相机贴画面边缘时裁剪框会越界，夹回图内保证 crop 不报错

### 1.3 裁剪 + 标准预处理

```python
crop = im.crop((xa,ya,xb,yb)).resize((240,180), Image.Resampling.BILINEAR)
x = torch.from_numpy(np.asarray(crop,np.float32)).permute(2,0,1)/255.
x = (x - torch.tensor([.485,.456,.406])[:,None,None]) \
    / torch.tensor([.229,.224,.225])[:,None,None]
```

与全图版完全同一套预处理（这在训练/推理两端也必须一致）：

```text
PIL (180,240,3) → permute → (3,180,240) → /255 → [0,1]
→ 减 ImageNet 均值除方差（[:,None,None] 广播成 (3,1,1)，逐通道独立）
```

均值方差用 ImageNet 统计量而不是自己数据的：**必须和预训练/惯用分布对齐**。

### 1.4 角点坐标换算进小图（q）

```python
q = (p-[xa,ya]) * [240/(xb-xa), 180/(yb-ya)]
```

数学上每分量独立两步：

```text
q_x = (p_x − xa) × sx，  sx = 240/(xb−xa)   # 水平：平移后缩放
q_y = (p_y − ya) × sy，  sy = 180/(yb−ya)   # 竖直：系数可以和 sx 不同！
```

**关键约束**：sx、sy 必须与 `resize((240,180))` 内部重采样系数**完全一致**——
图和坐标用同一套"搬家规则"，峰才落得准。裁剪框宽高比不是 4:3 时两个系数不同，
若共用一个系数，小图就被拉变形、坐标错位。

广播：`p (8,2) − [xa,ya] (2,)` → 逐行做同样减法，结果 (8,2)。

### 1.5 画单峰高斯

```python
yy, xx = np.mgrid[0:180,0:240]        # 两张坐标垫板：xx[y,x]=x, yy[y,x]=y
h = np.zeros((8,180,240), np.float32)
sigma = max(2., min(x2-x1, y2-y1) * 240/(xb-xa) / 18.)
for c,(u,v) in enumerate(q):
    h[c] = np.exp(-((xx-u)**2 + (yy-v)**2) / (2*sigma*sigma))
```

逐项拆：

- **mgrid 垫板**：高斯要回答"每个像素离峰多远"，但矩阵只有值没有坐标——
  mgrid 把坐标也造成 (180,240) 矩阵，与像素逐格配对。注意行=y 在前
- **sigma 自适应**：`min(矩形宽,矩形高)` 是目标投影尺寸 → 乘 x 缩放系数换算到小图
  → 除 18（目标约 1/18 当 σ）→ 下限 2 像素防退化。
  ROI 里相机忽大忽小，固定 σ 会"小目标峰粘连、大目标信号稀疏"
- **高斯公式**：`(xx-u)²+(yy-v)²` 是每像素到峰的距离²（勾股），
  `exp(−距离²/2σ²)` 把距离翻译成概率：峰顶 1.0，1σ 处 0.61，3σ 外 ≈0.01
- **直接赋值 h[c]=**：单实例每通道只有一个峰，无需像全图版那样用 `np.maximum`
  防两实例峰重叠相加——这是 ROI 设计的"单峰红利"

**实测验证**（真实样本，8 通道整数 argmax 与连续真值 q 的偏差）：

```text
通道 0~7 偏差：0.33 / 0.04 / 0.33 / 0.23 / 0.39 / 0.50 / 0.50 / 0.43 像素
峰顶 h.max() ≈ 0.9999（连续中心不压整数格时略低于 1，正常现象）
```

### 1.6 返回

```python
return {'image': x,                     # (3,180,240) 网络输入
        'heatmap': torch.from_numpy(h), # (8,180,240) 训练目标
        'corners': torch.from_numpy(q), # (8,2) 小图角点真值（fine损失/评估备用）
        'id': r['id']+'_'+str(ins['instance_id'])}   # 每样本唯一名，便于排查
```

## 二、网络构建：BoxDreamerSingle.__init__ 逐层

文件：`pose3d/boxdreamer_single.py:42-61`。超参 `patch=15, dim=256, depth=6, heads=8`。

| 层 | 定义 | 参数量 | 角色 |
|---|---|---|---|
| `image_embed` | `Conv2d(3, 256, 15, 15)` | 173K | patchify+投影一步完成 |
| `pos` | `Parameter(1, 192, 256)` | 49K | 位置编码（原 query/pos 已合并） |
| `transformer` | 6 层 `TransformerEncoderLayer` | 4.74M | 唯一的"思考"环节 |
| `norm + head` | `LayerNorm(256)` + `Linear(256, 1800)` | 463K | 出口：token→热图块 |
| **合计** | | **5.42M** | |

> 2026-09 裁剪：参考热图分支（heatmap_embed, 461K）与 query 表（49K）已删除——
> 目标仅"8 角点热图 + 提峰"，无参考图；query 与 pos 数学上只有和起作用，合并为一个表。
> head 偏置初始化 −4：稀疏目标下让初始预测接近 0（而非 sigmoid 中点 0.5）。

关键定义：

```python
layer = nn.TransformerEncoderLayer(dim, heads, dim*4, dropout,
                                   batch_first=True, norm_first=True, activation="gelu")
self.transformer = nn.TransformerEncoder(layer, depth, enable_nested_tensor=False)
```

- `batch_first=True`：输入 (B, 序列, 特征)，与 forward 产出格式一致
- `norm_first=True`（Pre-LN）：从零训练更稳、免 warmup
- `dim*4=1024`：MLP 中间宽度，标准配比
- `enable_nested_tensor=False`：显式关闭与 Pre-LN 不兼容的加速路径（消除警告）

`pos` 是**裸可学习表**（没有输入可乘，职责是"位置身份"而非"变换"），
初始化用 `trunc_normal_(std=0.02)`（ViT 惯例，全零训不动）。
（原设计的 query 与 pos 只以和的形式参与，已合并为这一个表。）

## 三、前向传播：forward 形状全追踪

文件：`pose3d/boxdreamer_single.py:63-73`。

```python
z = self.image_embed(image).flatten(2).transpose(1, 2)
```

```text
image (B,3,180,240)
  │ Conv2d(3→256, k=15, s=15)：每个 15×15 patch 不重叠盖住，
  │ 与 256 个核内积 → 256 维（数学上等价 Linear(675,256)）
  ▼ (B,256,12,16)
  │ flatten(2)：第 2 维起压平 → (B,256,192)
  │ transpose(1,2)：token 变"行" → (B,192,256)
```

```python
z = self.transformer(z + self.pos)
```

```text
(B,192,256) + (1,192,256)   广播加：注入位置身份
  │ 6 层自注意力（每层内部：LayerNorm → 8头MSA → 残差 → LayerNorm → MLP(256→1024→256) → 残差）
  ▼ (B,192,256)   形状不变，但每个 token 已融合全图 192 个 token 的信息
```

```python
y = self.head(self.norm(z)).transpose(1, 2)
```

```text
(B,192,256) → LayerNorm → Linear(256→1800) → (B,192,1800)
  每个token预测"自己负责的那块 8通道×15×15 区域"的热图值
  transpose(1,2)：(B,192,1800) → (B,1800,192)
  ← 从"token为行"的 Transformer 格式，切到"块为列"的 fold 格式
```

```python
y = F.fold(y, output_size=(180,240), kernel_size=15, stride=15)
return torch.sigmoid(y)
```

```text
(B,1800,192) → fold 把第 k 列 reshape 成 (8,15,15) 放回网格第 k 格
  （stride=kernel 无重叠，无相加歧义）→ (B,8,180,240)
  sigmoid 压到 [0,1] → 预测热图，与标签同构
```

## 四、训练循环：train_heatmap.py

两种架构可选（`--arch`）：

| | `scratch`（默认） | `dinov2`（论文方案） |
|---|---|---|
| 结构 | 从零 5.42M 小 Transformer | **冻结 DINOv2**（`--dinov2-variant small/base/large`）+ 1.2M 卷积解码头 |
| 预训练 | 无 | ImageNet 自监督（论文 Sec 3.2 同源） |
| 可训练参数 | 5.42M | ~1.2M（backbone 冻结） |
| 域差距抗性 | 弱 | **强**（DINOv2 鲁棒特征，合成→真实关键） |
| 显存/速度 | 最轻 | base 版游戏本轻松 |

```bash
# DINOv2-Base（论文同款）：
python -m pose3d.train_heatmap --roi --arch dinov2 --dinov2-variant base \
  --epochs 30 --batch-size 16 --workers 4 --amp
```

checkpoint 内记录 `arch`/`dinov2_variant`，`VideoPosePipeline` 加载时自动
重建对应网络，无需手工指定。

```python
ds = DatasetClass(args.root, "train"); va = DatasetClass(args.root, "val")
dl = DataLoader(ds, args.batch_size, shuffle=True, ...)
net = BoxDreamerSingle().to(device)
opt = torch.optim.AdamW(net.parameters(), lr=1e-4, weight_decay=1e-4)
```

每个 epoch：

```python
for b in dl:
    p = net(b["image"].to(device))                    # (B,8,180,240)
    loss = heatmap_loss(p, b["heatmap"].to(device))   # 前景加权 SmoothL1
    opt.zero_grad(set_to_none=True)
    loss.backward()                                   # 梯度流回全部 5.42M 参数
    opt.step()
# 验证集算 val loss，历史最优才存 checkpoint
torch.save({"model": net.state_dict(), "epoch": ..., "val_loss": ...}, path)
```

要点：

- **前景加权损失**：热图目标 ~99.7% 是背景，普通 SmoothL1 会让网络学会
  "全图预测 0"（loss 卡 0.005、峰位误差 ~100px 不动，已实测复现）。
  `weights = 1 + 100×target` 让峰区像素主导梯度；配合 head 偏置 −4 初始化
  （初始预测 ≈0 而非 0.5），2 样本过拟合冒烟 300 步峰位误差 101px → 1.1px
- 论文的 fine 项（`L = L_coarse + 2.0·L_fine`，角点坐标监督）仍未实现，
  是下一个精度提升点（数据已备好：`corners` 字段）
- 按 **val loss 最优**存档，防过拟合选型

## 五、推理链路：VideoPosePipeline.__call__ 逐步

文件：`pose3d/roi_pipeline.py:85-102`。每帧执行：

### ① 检测

```python
boxes, scores = YOLO 预测
ids = np.argsort(scores)[::-1][:2]      # 置信度降序取前 2
```

隐含假设：**两台相机就是置信度最高的两个检测**。误检挤掉相机会连锁出错
——`detect_image.py` 存在的意义就是单独验收这一环。

### ② 裁剪（与训练严格同构）

```python
pw, ph = (x2-x1)*self.crop_pad, (y2-y1)*self.crop_pad     # 15% 外扩
crop → resize (240,180) → 同一套归一化
```

### ③ 前向 + ④ 提峰

```python
hm = self.net(x[None].to(device))[0].cpu().numpy()        # (8,180,240)
p = extract_peaks(hm)
```

`extract_peaks` 每通道：

```python
_, mx, _, loc = cv2.minMaxLoc(c)     # 全图最大值及位置
if mx < 0.15: → [nan, nan]           # 峰太矮 = 角点不可见（遮挡/出画面）
取峰顶 3×3 邻域 → 加权质心:
坐标 = Σ(位置×响应)/Σ响应            # 亚像素，思想同双线性插值
```

不用裸 argmax 的原因：格点坐标是整数，真实峰心常在像素之间，
量化误差最大 1px；加权质心"哪边响应强往哪边挪"。

### ⑤ 坐标逆换算回原图

```python
p[:,0] *= (xb-xa)/240.;  p[:,1] *= (yb-ya)/180.;  p += [xa, ya]
```

这是**训练时 q 换算的精确逆运算**（乘缩放比的倒数再加回裁剪偏移）。
两处必须严格对偶——训练在小图学"峰在哪"，PnP 在原图解位姿，全靠这层换算不出错。

### ⑥ PnP

```python
ok = np.isfinite(p).all(1)              # 过滤 NaN 角点
if ok.sum() >= 4:                        # PnP 最少 4 点
    cv2.solvePnPRansac(self.obj[ok], p[ok], self.K, self.dist,
                       flags=cv2.SOLVEPNP_SQPNP)
```

- `obj`：8 个 3D 角点（mm，模型坐标系），由 `models_info.json` 按
  **XYZ 二进制计数序**拼出（x 最慢 z 最快），与热图通道序严格一致
- `K`：`camera.json` 的内参（合成 82° FOV 推导，真实视频应换实测标定）
- Ransac 版顺带做内点筛选，个别坏角点不至于污染整个解
- 输出 rvec/tvec = 旋转/平移，t 单位 mm

### ⑦ EMA 时序平滑

```python
r.rvec = alpha*r.rvec + (1-alpha)*prev.rvec     # alpha=0.65
```

每帧独立解算有噪声，EMA 让位姿"跟着历史走"。配套简易身份匹配：
每帧按检测框 x 排序、180px 内视为同一台。已知短板：两机交叉换位会认错人；
rvec 线性平均在 ±π 附近跳变——升级路线为匈牙利匹配 + 四元数 SLERP。

## 六、对偶关系总表（两端必须一致的东西）

| 项目 | 训练端 | 推理端 |
|---|---|---|
| 裁剪/缩放 | `RoiPoseDataset` 按 GT 角点裁 | YOLO 框裁，**同样外扩 15%** |
| 预处理 | permute/255/ImageNet 归一化 | 同一套（`roi_pipeline.py:92-93`） |
| 坐标换算 | `q=(p−[xa,ya])×[sx,sy]` | `p=q×[1/sx,1/sy]+[xa,ya]` 互逆 |
| 角点通道序 | `corner_channel_order_mm`（XYZ 二进制） | `run_video.py` 拼同一顺序的 obj 点 |

任何一处不对偶，表现为：训练 loss 正常下降、推理 PnP 结果却完全错乱。

## 七、已知短板与下一步

1. fine 损失（2.0·L_fine）未实现——数据已备好（`corners` 字段），优先级最高
2. σ 公式 y 短边乘 x 缩放系数，轻微各向异性偏差
3. YOLO 权重（`dji_action4_yolo.pt`）尚未训练——推理链的前置缺口
4. EMA 匹配在目标交叉时失效；rvec 平均应换 SLERP
5. 相机内参按 82° FOV 推导，最终精度需真实标定
6. 数据 1475 张（目标 2000），补齐后需重跑标签与训练
