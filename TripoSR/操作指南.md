# TripoSR 本地部署操作指南

> 环境：macOS (Apple Silicon) · conda 环境 `pose3d` · Python 3.10 · CPU 推理
> 用途：输入单张图片，生成 3D 模型（OBJ/GLB），单张约 20 秒

---

## 一、日常使用（只需看这一节）

### 1. 激活环境

```sh
conda activate pose3d
cd ~/Code/编程考核/TripoSR
```

### 2. 生成 3D 模型

```sh
HF_HUB_OFFLINE=1 python run.py 图片路径.png \
    --pretrained-model-name-or-path models/TripoSR \
    --output-dir output/
```

- 支持一次传多张图，用空格分隔：`python run.py a.png b.png c.png ...`
- 输出在 `output/<序号>/mesh.obj`（顶点色），`input.png` 是抠图后的输入
- 全程 CPU 推理，单张约 20 秒

### 3. 常用参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--bake-texture` | 关 | 烘焙贴图（输出 `texture.png`，替代顶点色） |
| `--texture-resolution` | 2048 | 贴图分辨率，需配合 `--bake-texture` |
| `--model-save-format` | obj | 可选 `obj` / `glb`。**注意：用 `--bake-texture` 时必须选 `obj`**（xatlas 导出的实际是 OBJ 文本，扩展名写 glb 也无济于事） |
| `--mc-resolution` | 256 | marching cubes 网格分辨率，调高细节更多、更慢 |
| `--render` | 关 | 输出 30 帧旋转视频 `render.mp4` |
| `--no-remove-bg` | 关 | 跳过自动抠图（要求输入为灰底、前景比例合适的 RGB 图） |
| `--foreground-ratio` | 0.85 | 前景占图比例 |
| `--device` | cuda:0 | 本机无 CUDA 自动回退 CPU，无需设置 |

### ⚠️ 必须带 `HF_HUB_OFFLINE=1` 和本地模型路径

原因见[第四节](#四网络限制与离线方案)：
- 本机网络直连不了 huggingface.co；
- `models/TripoSR/` 是已下载好的本地权重（config.yaml + model.ckpt）；
- `HF_HUB_OFFLINE=1` 让程序只读本地缓存，不去联网（否则每个请求要重试 6 次才报错，非常慢）。

## 三、环境搭建完整记录（复现用）

### 3.1 安装依赖

```sh
conda activate pose3d
pip install omegaconf einops "transformers>=4.46,<5" \
    "imageio[ffmpeg]" moderngl "rembg[cpu]" gradio
```

要点：
- transformers 必须锁 4.x —— 仓库代码用 `ViTModel.config_class.from_pretrained()` 和 `interpolate_pos_encoding`，5.x 有破坏性变更；
- `rembg[cpu]` 的 `[cpu]` 必须带，否则不装 onnxruntime，`import rembg` 会失败；
- torch / torchvision 用环境里已有的，无需安装。

### 3.2 编译 torchmcubes（含 CMake 补丁）

torchmcubes 只在 GitHub 发布（PyPI 没有），且其 `CMakeLists.txt` 写死 `CMAKE_CXX_STANDARD 17`，
与 torch 2.14 要求的 C++20 冲突（报错 `C++20 or later compatible compiler is required to use PyTorch`），
需要先改补丁再编译。

**补丁后源码已保存在 `third_party/torchmcubes/`**（第 28 行已改为 `set(CMAKE_CXX_STANDARD 20)`），
重装直接：

```sh
pip install third_party/torchmcubes
```

如果需要从零重建补丁：

```sh
# 直连 GitHub 超时时，用 codeload 子域下载（实测可通）：
curl -sL https://codeload.github.com/tatsy/torchmcubes/tar.gz/refs/heads/master -o torchmcubes-master.tar.gz
tar -xzf torchmcubes-master.tar.gz && cd torchmcubes-master
# 编辑 CMakeLists.txt：把 set(CMAKE_CXX_STANDARD 17) 改为 20
pip install .
```

### 3.3 下载模型权重到本地

TripoSR 权重（`config.yaml` + `model.ckpt`，共约 1.6GB）已下载到 `models/TripoSR/`。
如需重新下载（用 curl，不能用 Python）：

```sh
mkdir -p models/TripoSR
curl -L "https://hf-mirror.com/stabilityai/TripoSR/resolve/main/config.yaml" -o models/TripoSR/config.yaml
curl -L "https://hf-mirror.com/stabilityai/TripoSR/resolve/main/model.ckpt" -o models/TripoSR/model.ckpt
# 断点续传：加 -C - 参数
```

### 3.4 下载 rembg 抠图模型

已放在 `~/.u2net/u2net.onnx`（176MB），rembg 启动时自动读取，无需操作。
重新下载（GitHub releases 被墙时走加速镜像）：

```sh
mkdir -p ~/.u2net
curl -L "https://ghfast.top/https://github.com/danielgatis/rembg/releases/download/v0.0.0/u2net.onnx" \
    -o ~/.u2net/u2net.onnx
```

### 3.5 构造 DINO 配置的 HF 本地缓存

模型构建时需要 `facebook/dino-vitb16` 的 `config.json`（仅配置，权重在 model.ckpt 里）。
已手动放入 HF 缓存 `~/.cache/huggingface/hub/models--facebook--dino-vitb16/`，无需操作。
重新构造：

```sh
CACHE=~/.cache/huggingface/hub/models--facebook--dino-vitb16
# 先用 HEAD 请求拿 commit hash（下面 f205d5d8... 是当时的值，以实际返回为准）
curl -sI "https://hf-mirror.com/facebook/dino-vitb16/resolve/main/config.json" | grep -i x-repo-commit
mkdir -p "$CACHE/snapshots/<commit>" "$CACHE/refs"
printf "<commit>" > "$CACHE/refs/main"
curl -L "https://hf-mirror.com/facebook/dino-vitb16/resolve/main/config.json" \
    -o "$CACHE/snapshots/<commit>/config.json"
```

### 3.6 验证安装

```sh
python -c "
from torchmcubes import marching_cubes
from tsr.system import TSR
print('OK')
"
```

## 四、网络限制与离线方案

本机网络环境：
- **huggingface.co 直连不通**（TLS 握手被重置）；
- **hf-mirror.com 拦截 Python 客户端**：对 Python 的 TLS 指纹返回 308 重定向回 huggingface.co（curl 不受影响），
  所以 `huggingface_hub` / `transformers` 的在线下载全部不可用；
- **github.com 直连超时**，但 `codeload.github.com` 和第三方加速镜像（ghfast.top 等）可用。

因此采用的方案：**所有模型文件 curl 下载到本地 + `HF_HUB_OFFLINE=1` 离线运行**。
代价是：不能自动更新模型、换其他 HF 模型时需按 3.3/3.5 的方式手动下载。

## 五、常见问题

| 现象 | 原因与解决 |
|---|---|
| 卡在 `Initializing model` 后报 SSLError | 忘了加 `HF_HUB_OFFLINE=1`（每个请求要重试 6 次） |
| 报 `No such file or directory: 'models/TripoSR/model.ckpt'` | 没传 `--pretrained-model-name-or-path models/TripoSR` |
| 报 `C++20 or later compatible compiler is required` | torchmcubes 用了未打补丁的源码编译，用 `pip install third_party/torchmcubes` 重装 |
| 报 `No module named 'onnxruntime'` | 当时只装了 `rembg` 没带 `[cpu]`，补装 `pip install "rembg[cpu]"` |
| 首次运行卡在下载 u2net | `~/.u2net/u2net.onnx` 缺失，见 3.4 重新下载 |
| 想看效果视频 | 加 `--render`，输出 `render.mp4` |
| mesh 有破面/细节丢失 | 提高 `--mc-resolution 384`（更慢） |

> 注：`gradio_app.py`（网页界面）依赖的 gradio 6.x 与该脚本编写时的 4.x API 有差异，未验证可用；
> 命令行 `run.py` 为主要使用方式。
